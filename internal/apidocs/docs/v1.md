# MW Email API v1

This document describes the current MW Email HTTP contract. JSON endpoints use
`Content-Type: application/json`. Administrative endpoints are rooted at
`/admin/api`.

## Application email API

### Send email

```http
POST /v1/emails
Authorization: Bearer mw_live_...
Idempotency-Key: <stable-key>
Content-Type: application/json
```

This endpoint uses a project API key. Identity delegated tokens are not valid
project credentials.

## Federated administrative authentication

MW BFF calls administrative business endpoints with an opaque delegated token:

```http
Authorization: Bearer <delegated-token>
```

MW Email introspects the token and requires `aud=mw-mail` plus the scope listed
for the route. Federated requests do not use browser Origin or CSRF headers.

### Delete project

```http
DELETE /admin/api/projects/{id}
Authorization: Bearer <delegated-token>
X-Request-ID: <correlation-id>
```

Required scope: `mail.projects.delete`.

- `204 No Content`: the project and its API credential were deleted atomically.
- `404 Not Found`: the project does not exist or was already deleted.
- `409 Conflict`: retained email history prevents deletion.

The stable dependency response is:

```json
{
  "code": "project_has_dependencies",
  "error": "project has retained email history"
}
```

Deletion creates an immutable audit event containing the human actor, project
ID and name, request ID, and timestamp. Repeating a successful deletion is safe
and returns `404`; project IDs are matched exactly.

## Service and documentation

| Method and path | Scope | Success |
|---|---|---|
| `GET /admin/api/health` | `mail.projects.read` | `200` |
| `GET /admin/api/docs` | `mail.server.read` | `200` |
| `GET /admin/api/docs/{version}` | `mail.server.read` | `200` |

`GET /admin/api/docs` lists available snapshots. The version endpoint returns
the selected snapshot as `text/markdown`.

## Federated errors

- `401`: missing, malformed, inactive, or unverifiable credentials.
- `403`: wrong audience or missing required scope.
- `404`: the requested resource does not exist.
- `409`: the operation conflicts with retention policy.
